# srt-to-audio

Озвучивает субтитры в формате **SRT** и сохраняет результат в **MP3**.
Синтез речи работает через [edge-tts](https://github.com/rany2/edge-tts) —
бесплатный онлайн-сервис Microsoft Edge, ключи API не нужны (только интернет).
По умолчанию используется мужской русский голос `ru-RU-DmitryNeural`,
другие варианты — в разделе [«Голоса»](#голоса).

## Установка

Требуется Python 3.9+ и доступ в интернет (речь синтезируется онлайн через
сервис edge-tts). Скрипт одинаково работает на **macOS**, **Windows 11** и
**Ubuntu/Debian**, дополнительных программ (ffmpeg и т.п.) не нужно.

### macOS

```bash
cd srt-to-audio
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

### Windows 11 (PowerShell)

```powershell
cd srt-to-audio
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Если PowerShell блокирует активацию окружения, один раз выполните
`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` — либо не активируйте
окружение, а запускайте скрипт напрямую:
`.venv\Scripts\python.exe main.py`.

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip
cd srt-to-audio
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Быстрый старт

1. Положите файл субтитров в папку `input` (например, `input/lesson.srt`).
2. Запустите из корня проекта:

```bash
python main.py          # macOS / Linux / Windows (в активированном окружении)
python3 main.py         # macOS / Linux, если окружение не активировано
```

Без активации окружения:

```bash
.venv/bin/python main.py            # macOS / Linux
.venv\Scripts\python.exe main.py    # Windows
```

3. Готовый файл появится в папке `output` (`output/lesson.mp3`).

## Использование

```bash
python main.py                            # озвучить все .srt из папки input
python main.py -f lesson.srt              # только один файл
python main.py -f lesson.srt -o voice     # своё имя результата (output/voice.mp3)
python main.py --voice ru-RU-SvetlanaNeural # выбрать голос (женский)
python main.py --rate "+10%" --pitch "-20Hz"   # темп и тон (кавычки — для PowerShell)
python main.py --list-voices ru           # список доступных голосов
python main.py --overwrite                # перезаписать существующие mp3
python main.py --no-fit                   # озвучить подряд, без привязки к таймкоду
python main.py --block-seconds 8          # укрупнять блоки до 8 с вместо 12
python main.py --align end                # прижимать озвучку к концу блока
```

Все ключи:

| Ключ | Назначение |
| --- | --- |
| `-f`, `--file` | имя файла из папки `input` или полный путь |
| `-o`, `--out` | имя выходного файла без расширения (только для одного входа) |
| `--voice` | голос edge-tts, например `ru-RU-SvetlanaNeural` |
| `--rate` | темп речи: `+10%`, `-20%` |
| `--volume` | громкость: `+0%`, `-50%` |
| `--pitch` | тон: `+0Hz`, `-20Hz` |
| `--overwrite` | разрешить перезапись готовых mp3 |
| `--no-fit` | озвучить реплики подряд, без расстановки по таймкоду и ускорения |
| `--block-seconds СЕК` | до какой длительности укрупнять блоки озвучки (`0` — по реплике) |
| `--align auto\|start\|end` | куда ставить блок в его окне (по умолчанию `auto`) |
| `--list-voices [ЯЗЫК]` | показать голоса (можно отфильтровать по языку) |
| `--config` | путь к альтернативному файлу настроек |

Коды возврата: `0` — успех, `1` — часть файлов не удалось обработать,
`2` — ошибка настроек или аргументов, `130` — прервано пользователем.

## Настройки

Все параметры хранятся в `config.json` в корне проекта:

```json
{
  "paths": {
    "input_dir": "input",
    "output_dir": "output",
    "output_extension": ".mp3"
  },
  "voice": {
    "name": "ru-RU-DmitryNeural",
    "rate": "+0%",
    "volume": "+0%",
    "pitch": "+0Hz"
  },
  "processing": {
    "chunk_max_chars": 3000,
    "overwrite": false,
    "retries": 4,
    "fit_timeline": true,
    "max_rate_percent": 100,
    "block_max_seconds": 12,
    "block_align": "auto",
    "block_gap_max_seconds": 2
  }
}
```

| Параметр | Описание |
| --- | --- |
| `paths.input_dir` / `paths.output_dir` | папки входа и выхода; относительные пути считаются от расположения `config.json` |
| `paths.output_extension` | расширение результата (по умолчанию `.mp3`) |
| `voice.name` | голос синтеза (`python main.py --list-voices ru`) |
| `voice.rate` / `voice.volume` / `voice.pitch` | темп, громкость, тон |
| `processing.chunk_max_chars` | предел текста в одном запросе к сервису; блоки длиннее режутся на части, и окно блока делится между ними |
| `processing.overwrite` | перезаписывать ли существующие файлы |
| `processing.retries` | сколько раз повторять запрос при сбое сервиса (пауза между попытками растёт: 2, 4, 8, 15 секунд) |
| `processing.fit_timeline` | расставлять ли блоки по таймкоду и ускорять те, что не влезают в своё окно (см. ниже) |
| `processing.max_rate_percent` | предел автоускорения отдельного блока, в процентах (0–100); остальные блоки всегда читаются в темпе `voice.rate`, а блоки короче окна — без замедления |
| `processing.block_max_seconds` | до какой длительности укрупнять блоки озвучки; `0` — озвучивать каждую реплику отдельно |
| `processing.block_align` | куда ставить блок внутри его окна: `auto` (по умолчанию), `start`, `end` |
| `processing.block_gap_max_seconds` | пауза в субтитрах, которая ещё остаётся внутри блока (по умолчанию 2 с): короткие паузы возвращаются тишиной внутрь озвучки, длинные — режут блок |

Значения из командной строки имеют приоритет над `config.json`.
Пропущенные параметры берут значения по умолчанию, неизвестные — считаются ошибкой.

## Как это работает

1. Из папки `input` читаются файлы `.srt` (кодировки UTF-8, UTF-8 с BOM, CP1251).
2. Субтитры разбираются на реплики, из текста убирается разметка (`<i>`, `{\an8}` и т.п.).
3. Соседние реплики укрупняются в блоки примерно по 12 секунд
   (`processing.block_max_seconds`) и озвучиваются одним запросом к edge-tts:
   голос читает их слитно, как синхронный перевод, не разрываясь на каждой
   строке субтитров. Пауза длиннее 2 секунд
   (`processing.block_gap_max_seconds`) внутри будущего блока его режет, чтобы
   озвучка не «перепрыгивала» молчание в кадре. Паузы покороче остаются внутри
   блока, но возвращаются на своё место тишиной: синтезатор читает блок слитно,
   и без этого вторая-третья реплики блока звучали бы раньше своих таймкодов.
   Тишина вставляется перед первым словом следующей реплики, так что реплика
   может прозвучать чуть позже картинки, но не раньше неё. Паузы занимают только
   свободное время окна: если речь и без них заполняет окно, пауза ужимается или
   пропускается — ускорять из-за пауз речь не приходится.
4. Блоки собираются в один mp3 по таймкоду: время от начала дорожки до блока
   заполняется тишиной (кадры-пустышки в том же формате, без ffmpeg), поэтому
   речь звучит одновременно с соответствующим кадром видео.
5. Темп правится только там, где это нужно: блок, который не влезает в своё окно,
   ускоряется (до `processing.max_rate_percent`). Блок, речь которого короче окна,
   читается в обычном темпе `voice.rate`, а остаток окна остаётся тишиной —
   замедление звучало бы неестественно. Отключить всю привязку к таймкоду можно
   ключом `--no-fit`.
6. Результат сохраняется в `output`.

Озвучивается именно текст субтитров: паузы между блоками берутся из их
временных меток, а не из знаков препинания.

### Как озвучка попадает в таймкод

Синтезатор читает текст в своём темпе, и он не совпадает с темпом исходной
речи: в плотных субтитрах голос не успевает, в разреженных — наоборот,
заканчивает раньше. Раньше это лечилось общим темпом на весь файл, но тогда
речь «уезжала» относительно видео: ускоренный голос заканчивал реплику раньше,
чем она появляется в кадре, и весь дальнейший звук смещался. Сейчас так:

- каждый блок ставится в своё окно по таймкоду (`00:00:12,500` → 12,5 с
  от начала mp3), недостающее время до него заполняется тишиной;
- паузы из субтитров, которые остались внутри блока, возвращаются тишиной
  перед первым словом следующей реплики — ровно настолько, насколько в окне
  есть свободное место. Без этого слитно прочитанный блок «съедал» бы паузы,
  и его вторая-третья реплики звучали бы раньше своих таймкодов;
- внутри окна блок размещается как у синхронного переводчика
  (`processing.block_align`):
  - `auto` — если речь в обычном темпе укладывается в окно, она звучит с
    начала блока и занимает его целиком до своего конца (остаток окна —
    пауза); если блок пришлось ускорять, речь прижимается к концу окна, чтобы
    закончить вместе с оригиналом;
  - `start` — всегда с начала окна;
  - `end` — всегда к концу окна;
- блок, который не влезает в окно, переозвучивается с ускорением, и только он:
  соседние блоки остаются в своём темпе;
- блок, речь которого короче окна, не замедляется: он читается в обычном темпе,
  а остаток окна остаётся тишиной — так голос звучит естественно и не «тянет»
  слова;
- если ускорение уже на пределе `processing.max_rate_percent`, а блок всё равно
  не влез, программа сообщает об этом: такой блок начнётся раньше своего
  таймкода и сдвинет звук после себя.

Пример: окно 10,0 с, а блок в обычном темпе читается 13,0 с. Программа
переозвучит его с темпом `+30 %` (13 / 1,3 = 10,0 с) и прижмёт к концу окна,
то есть речь закончится ровно там, где заканчиваются субтитры.
Обратный случай: окно 12,0 с, а блок в обычном темпе читается 9,0 с — значит,
исходная речь медленная. Замедлять озвучку программа не будет: блок прочитают
в обычном темпе (9,0 с из 12,0 с), а остаток окна останется тишиной.

Ещё две детали:

- edge-tts добавляет к каждой реплике служебную тишину (около 0,25 с в начале
  и до секунды в конце). Она обрезается по отметкам слов, иначе паузы «съедались»
  бы, а озвучка уезжала вперёд.
- блоки озвучиваются отдельными запросами (по три запроса одновременно), но их
  стало в разы меньше, чем реплик, поэтому файл обрабатывается быстрее: блок из
  12 секунд речи — это один запрос вместо пяти-шести.
  Точность попадания в таймкод — около 0,1 с.

## Структура проекта

```
main.py                   точка входа
config.json               настройки
requirements.txt          зависимости
srt_to_audio/
    config.py             загрузка и проверка настроек
    srt_parser.py         чтение и разбор SRT
    tts.py                обёртка над edge-tts (аудио + границы речи)
    mp3.py                длительность, тишина и обрезка mp3 по фреймам (без зависимостей)
    converter.py          логика «srt -> mp3»
    cli.py                аргументы, прогресс, вывод ошибок
input/                    исходные субтитры
output/                   готовые mp3
```

## Если что-то не работает

| Сообщение | Что делать |
| --- | --- |
| `Папка с субтитрами не найдена` | создайте папку `input` или поправьте `paths.input_dir` |
| `В папке ... нет файлов .srt` | положите файл субтитров в `input` |
| `Не удалось получить аудио от edge-tts` | проверьте интернет и доступность сервиса, повторите запуск |
| `Сервис edge-tts не вернул аудио` | временная блокировка сервиса (слишком частые запросы): подождите пару минут и повторите запуск |
| `Файл уже существует` | удалите mp3 или добавьте `--overwrite` |
| `не влезло даже на пределе темпа` | речи слишком много для окна блока: увеличьте `processing.max_rate_percent`, уменьшите `processing.block_max_seconds` или задайте более быстрый `voice.rate` |
| `Не удалось определить кодировку` | пересохраните субтитры в UTF-8 |
| `python: command not found` | используйте `python3` (macOS/Linux) или `py` (Windows) |
| `No module named venv` (Debian/Ubuntu) | `sudo apt install python3-venv` |
| `ModuleNotFoundError: edge_tts` | окружение не активировано: `pip install -r requirements.txt` |

## Кроссплатформенность

- Пути собираются через `pathlib`, разделители каталогов подставляются системой;
  в `config.json` можно писать и относительные, и абсолютные пути.
- Вывод принудительно переводится в UTF-8, поэтому русский текст не ломает
  консоль Windows; при перенаправлении вывода в файл кодировка также UTF-8.
- Индикация прогресса перерисовывает одну строку только в терминале; при
  перенаправлении в файл/пайп печатаются лишь ключевые шаги.
- Внешних утилит нет: синтез идёт по сети, файлы пишутся средствами Python.
